# Домашние церкви Ижевска

Telegram-бот и Mini App с единым PostgreSQL-хранилищем. Каталог `/app`, защищённая админка `/admin`, проверка работоспособности `/health`.

## Возможности

- Список, карточки, фильтр по району, карта OpenStreetMap, ближайшие группы и маршрут.
- Церкви читаются из БД, изменения в админке сразу видны в боте и Mini App.
- Заявки из Telegram и Mini App сохраняются транзакционно. Повторное обращение того же Telegram-пользователя в ту же церковь возвращает существующую заявку, включая закрытую.
- Статусы заявок: `new`, `contacted`, `closed`. Список и карточка заявки доступны только администратору.
- Администратор добавляет и редактирует группы, может скрыть их, сохранив все заявки. Физического удаления через API нет.
- Telegram long polling и HTTP работают в одном процессе. PostgreSQL advisory lock допускает только один poller данного бота во время смены деплоя; новый процесс ждёт завершения старого. Webhook сбрасывается без удаления ожидающих обновлений.
- При настроенном `ADMIN_CHAT_ID` после сохранения заявки выполняется уведомление. Ошибка уведомления не отменяет заявку; автоматических повторов уведомления нет, админка остаётся источником истины.

## Render: существующий Web Service

1. Создайте PostgreSQL в том же регионе, что и сервис (Oregon).
2. В Environment сервиса добавьте `DATABASE_URL` = **Internal Database URL** базы. Не помещайте URL в код или README.
3. Оставьте существующий `BOT_TOKEN`. Для защищённой админки задайте `ADMIN_USERNAME=admin` и уникальный `ADMIN_PASSWORD` длиной не менее 16 символов.
4. Для первого заполнения установите `SEED_TEST_DATA=true`. Миграция и seed автоматически выполняются перед стартом HTTP/polling. Seed заполняет только пустой каталог и не меняет существующие записи.
5. Build Command: `pip install -r requirements.txt`.
6. Start Command: `python bot/main.py` (также поддерживается `python -m bot.main`). Root Directory — корень репозитория.
7. Health Check Path: `/health`. Затем Deploy latest commit.
8. Проверка: `/health` возвращает `status=ok`, `database=ok`, `polling=running` (кратковременно `standby` во время смены процесса); `/api/churches` возвращает каталог. Откройте `/start` в боте и отправьте тестовую заявку, проверьте её в `/admin` после повторного деплоя.

На бесплатном Web Service Render останавливает процесс при отсутствии HTTP-трафика; polling во время сна не работает. Для непрерывной работы нужен постоянно включённый тариф. Бесплатная PostgreSQL предназначена для прототипа и истекает через 30 дней: созданная 14 сентября 2026 база истекает **14 октября 2026**. До этой даты нужен переход на платный тариф или экспорт данных и перенос. [Документация Render](https://render.com/docs/free).

## Переменные окружения

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | Обязательный PostgreSQL URL (`postgres://`, `postgresql://`, `postgresql+asyncpg://`) |
| `BOT_TOKEN` | Токен BotFather; обязателен при включённом боте |
| `BOT_ENABLED` | По умолчанию `true`; `false` только для локальных HTTP-тестов |
| `SEED_TEST_DATA` | `true` для наполнения пустого каталога четырьмя тестовыми группами; по умолчанию `false` |
| `ADMIN_USERNAME` | Логин админки, по умолчанию `admin` |
| `ADMIN_PASSWORD` | Уникальный пароль от 16 символов; без него админка закрыта (503) |
| `ADMIN_CHAT_ID` | Необязательный Telegram chat ID для уведомлений о новых заявках |
| `WEB_APP_URL` | Необязательный публичный HTTPS URL; иначе используется `RENDER_EXTERNAL_URL` |
| `PORT` | HTTP-порт, Render задаёт автоматически; локально 10000 |

`.env` не загружается автоматически: переменные должны быть доступны процессу. `.env.example` содержит только шаблон. Все секреты храните в Render Environment или локальном исключённом `.env`.

## Миграции и тестовые данные

`bot/migrations` содержит последовательные миграции; применённые версии хранятся в `schema_migrations`. Первая миграция создаёт `churches` и `join_requests`, внешний ключ, ограничения и индексы. В PostgreSQL запуск миграций сериализуется транзакционной блокировкой. Для следующих изменений добавляйте новую версию и явные `ALTER`, не редактируйте уже применённую миграцию. Откат схемы с удалением данных намеренно не автоматизирован.

Ручной запуск инициализации:

```sh
python -m bot.database
```

`bot/seed_churches.json` используется только для наполнения БД. Все четыре группы отмечены `is_test=true`; лидеры, адреса и координаты — примеры. Telegram-контакты пустые, ссылки на вымышленных людей не выводятся. Для реальной группы администратор вводит проверенные данные и снимает отметку «Тестовая группа». Дополнительные реальные контакты для разработки не нужны.

Заявки прежней версии хранились в памяти и не могут быть восстановлены из репозитория. Бот прежней версии только отправлял уведомление; сохранённых записей в БД у него не было.

## API

| Метод / путь | Доступ / результат |
| --- | --- |
| `GET /`, `GET /health` | Проверка БД и процесса polling; при ошибке 503 |
| `GET /api/churches?district=...` | Активные группы |
| `GET /api/churches/{id}` | Карточка активной группы, иначе 404 |
| `POST /api/requests` | `{church_id: number, init_data: string}`; 201 для новой, 200 для повторной заявки |
| `GET /api/requests?status=new&limit=50&offset=0` | Только админ; limit 1–100, offset ≥ 0 |
| `GET /api/requests/{id}` | Только админ; карточка заявки |
| `PATCH /api/requests/{id}` | Только админ; `{status: "contacted"}` |
| `GET /api/admin/churches` | Только админ; включая скрытые |
| `POST /api/admin/churches` | Только админ; создание |
| `PUT /api/admin/churches/{id}` | Только админ; полная замена полей |

Поля церкви: `name`, `leader`, `leader_username` (null или username без @), `district`, `address`, `meeting`, `age`, `participants`, `interests` (массив строк), `description`, `lat`, `lon`, `is_test`, `active`. `id` назначает БД. Валидация отвергает неизвестные поля, неверные координаты и отрицательное число участников.

Mini App передаёт исходную `Telegram.WebApp.initData`. Сервер проверяет подпись BotFather-токеном и возраст до одного часа, извлекает Telegram ID/имя из подписанных данных. `initDataUnsafe` и переданный клиентом `telegram_id` не считаются удостоверением личности. В обычном браузере каталог доступен, отправить заявку можно через Telegram-бота.

Админка использует HTTP Basic Auth через HTTPS. Пароль не сохраняется в JavaScript/localStorage. Все административные изменения требуют заголовок `X-Admin-Request: 1`; CORS не включён, cross-site изменения запрещены. Тексты групп экранируются в HTML/Telegram. Ответы с данными не кэшируются. Для завершения сессии Basic Auth закройте приватное окно браузера; отдельного серверного logout нет.

## Локальная разработка и тесты

Python 3.12:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
export DATABASE_URL=sqlite+aiosqlite:///./local.db
export BOT_ENABLED=false
export SEED_TEST_DATA=true
python -m bot.main
```

SQLite — только вспомогательная локальная БД, на Render разрешён PostgreSQL. Для админки установите локальный `ADMIN_PASSWORD`; не используйте производственные секреты при тестировании. `backend/main.py` оставлен как совместимый запуск общего сервиса (`python -m backend.main`); старого отдельного FastAPI-хранилища в памяти больше нет.

```sh
python -m pytest -q
pip-audit -r requirements.txt
```

Тесты проверяют каталог, фильтр, карточки, подпись и срок Telegram initData, запрет подмены пользователя, сохранение/повторную инициализацию, отсутствие дубликатов, админ-доступ, CSRF, валидацию, скрытие церкви с сохранением заявок и отказ БД без ложного подтверждения.

Для интеграционного теста используйте **отдельную одноразовую PostgreSQL** в `TEST_DATABASE_URL` (не production). Этот тест добавляет тестовые заявки. GitHub Actions запускает PostgreSQL 18 и проверяет конкурирующие миграции, конкурентную отправку заявок и передачу блокировки polling, затем аудит зависимостей.
